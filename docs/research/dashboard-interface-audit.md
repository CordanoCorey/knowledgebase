# Dashboard and Shared Frame Product-Model Audit

Research ticket: [Audit the current interface against the product model](https://github.com/CordanoCorey/knowledgebase/issues/24)

Wayfinding map: [Wayfind the minimal daily Logeion workspace](https://github.com/CordanoCorey/knowledgebase/issues/23)

Audited: 2026-08-24

## Scope and method

This is a read-only audit of the rendered Dashboard and shared application frame. It compares the current React surfaces, their Convex data sources, integrated tests, and the existing shell prototypes with the canonical product sources and the approved decisions in the Wayfinding map. It does not select a new layout or implement changes.

The current main-worktree `CONTEXT.md` was read as the approved working copy, including its uncommitted definitions of Dashboard, Commonplace Book, Active Roles, Organization, To-do List, Subscription, and Notification. Those edits were deliberately not copied, staged, or committed on this research branch. Line references to that working copy are recorded as `CONTEXT.md (approved working copy):line`.

## Authoritative baseline

- The Dashboard is the active User's place at the Accessible Root Knowledge Context, and it is never an Organization dashboard (`CONTEXT.md` approved working copy:23-29, 207-209; [map #23](https://github.com/CordanoCorey/knowledgebase/issues/23)).
- The standard Knowledge Page Shell keeps the Knowledge Navigator, Contribution Editor, and Answer Feed, while avoiding repeated generic headings and empty rail placeholders ([`docs/product-core.md:101-121`](../../docs/product-core.md#L101)).
- Root Search finds existing accessible Tags independently of the Active Knowledge Context; the Knowledge Navigator Query Input searches or adds existing Tags inside the current context (`CONTEXT.md` approved working copy:27-29, 227-237; [`docs/product-core.md:147-153`](../../docs/product-core.md#L147)).
- Notifications are globally visible notices with read state independent of task resolution. To-do is the set of unresolved assigned Knowledge Slots and Review Slots, reached through the avatar menu rather than persistent navigation (`CONTEXT.md` approved working copy:435-456; [map #23](https://github.com/CordanoCorey/knowledgebase/issues/23)).
- Active Roles are plural: every applicable Role on the current Knowledge Page is active concurrently; there is no selected Role or role switcher (`CONTEXT.md` approved working copy:311-340; [map #23](https://github.com/CordanoCorey/knowledgebase/issues/23)).
- The approved Dashboard priority is: attention first; familiar places second; adding knowledge third; finding/requesting and browsing relevant knowledge tied next ([map #23](https://github.com/CordanoCorey/knowledgebase/issues/23)).

The approved plural Active Roles rule intentionally supersedes the older single-selected-role rule still present in [`docs/product-core.md:175-179`](../../docs/product-core.md#L175) and the earlier header/sidebar handoff ([`docs/handoffs/header-sidebar-navigation.md:73-75`](../../docs/handoffs/header-sidebar-navigation.md#L73)). This is a documentation conflict to reconcile, not an open prototype option.

## Executive finding

The reusable product core is present: the Dashboard is routed as the root Knowledge Page and already mounts the Knowledge Navigator, Contribution Editor, and Answer Feed; Root Search is distinct from context search; durable pins, bookmarks, notifications, Knowledge Slots, and Review Slots exist.

The unusable layer is the current composition around that core. The Dashboard adds a fixed school/ministry agenda, Bible-only recommendation block, generic metrics, root-wide feed selection, and multiple secondary control/empty-state regions. The shared frame implements the superseded single Active Role selector and exposes pins, To-do, account controls, and admin controls as separate persistent rail items. The result is neither a generalized User dashboard nor the approved daily priority order.

## Required Dashboard capabilities that are currently absent

1. **Notification preview:** the Dashboard only shows an unread number in the generic metric strip; it does not preview standard Notification cards or their destinations ([`src/App.tsx:3315-3347`](../../src/App.tsx#L3315)).
2. **Compact return area:** familiar, frequent/recent, and pinned Knowledge Pages are not combined on the Dashboard; pins only appear in persistent sidebar navigation ([`src/App.tsx:2130-2144`](../../src/App.tsx#L2130)).
3. **Relationship-based Organization prominence:** no Dashboard block ranks or highlights Organizations from the active User's relationships. The current Organization-specific prominence is hard-coded school/ministry copy, not personalization.
4. **Approved Answer Feed mix:** the Dashboard does not compose subscription-eligible content with popular/recommended content by Feed Priority.
5. **Missing-knowledge continuation:** the no-match Root Search state does not offer Add, identity confirmation, Question creation where appropriate, or a Knowledge Slot request path.
6. **At-a-glance daily priority:** the current order mounts the full root workspace and Answer Feed before the separate agenda ([`src/App.tsx:3226-3249`](../../src/App.tsx#L3226)); it does not visibly establish attention, return, add, find/request, and browse in the approved order.

These are gaps, not answers. Their interaction and visual forms remain owned by the open decision tickets.

## Safe removal boundary

- Remove hard-coded Dashboard fixtures and unsupported presentation; do **not** delete durable pins, bookmarks, subscriptions, notifications, Knowledge Slots, Review Slots, or their current routes merely because their access point will change.
- Preserve the standard Knowledge Page Shell on non-Dashboard Knowledge Pages. This audit does not authorize removing Knowledge Navigator, context search, Contribution Editor, or Answer Feed from defined Knowledge Contexts.
- Preserve sysadmin authorization and environment gating even if admin destinations move behind the avatar menu.
- Do not resolve exact header/sidebar placement, responsive behavior, final microcopy, ranking contracts, or rollout order in this report; the map explicitly leaves those unspecified.

## Decision-index wording

> The interface audit found that the reusable core is the root Knowledge Page workspace—Knowledge Navigator, compact Contribution Editor, Answer Feed, Root Search, and durable pin, bookmark, notification, and to-do models. The unusable layer is presentation: a hard-coded school/ministry agenda, Bible-only recommendations, redundant metrics and empty states, an unpersonalized root feed, and a shared frame built around one selected Active Role plus always-visible user/admin controls. Preserve the durable models and core surfaces; replace the Dashboard composition and shared-frame presentation through issues #25–#31.
